# LegendsViewer-AIPowered

> **This is a fork of [Kromtec/LegendsViewer-Next](https://github.com/Kromtec/LegendsViewer-Next).**
> All credit for the application — the XML parser, the object model, the prose generation and the
> whole Vue frontend — goes to [Kromtec](https://github.com/Kromtec) and the LegendsViewer-Next
> contributors. This fork is an unofficial personal project and is not affiliated with them.

**LegendsViewer-Next** is a tool for visualizing the rich history and data generated by the game
**Dwarf Fortress**. It works with the Steam release, parsing the exported legends XML, and is built
on a **.NET 10 backend** with a **Vue 3 / TypeScript** frontend.

## Why this fork exists

Upstream is built for a person browsing a world in a web UI. This fork adds a second way in, for
**programmatic analysis of a world** — tooling, text exports, and language models:

- responses in plain prose instead of Vuetify markup
- whole histories in one response instead of pages of ten
- search over names, over event text, and over object properties
- ownership and offices as queryable properties, which no event text contains
- reading a span of history by year, not only searching it for a word
- base rates and rankings, so a finding can be judged as common or rare

Everything is additive: the parsing and the object graph are upstream's, unchanged.

### Relationship to upstream

Changes live on `main` as new files; **no upstream source file has been modified**, so syncing
should not conflict in code. This file is the one deliberate exception, so expect a conflict here and
keep the fork's version. Nothing has been proposed upstream — this fork is not staging a pull
request. To follow upstream:

```bash
git remote add upstream https://github.com/Kromtec/LegendsViewer-Next.git
git fetch upstream
git merge upstream/main
```

## Features

- Overview and easy access to already opened worlds with thumbnails and timestamps
- Generated maps from parsed information of the exported XML plus files
- The most important information about a world at a glance
- Browse through paginated tables of **world objects**, including their historical details
- Interactive map powered by **Leaflet.js** for exploring the location of sites
- Look into the family trees of historical figures
- Load large Dwarf Fortress **XML exports** quickly and efficiently using **XmlReader**
- **Added by this fork:** an analysis API for reading and querying a world as text — see
  [ANALYSIS-API.md](ANALYSIS-API.md)

## Download

Self-contained builds — no .NET runtime needed. Get them from the
[latest release](https://github.com/Hadows/LegendsViewer-AIPowered/releases/latest):

| File | Platform |
|---|---|
| `LegendsViewer-<version>-win-x64.zip` | Windows x64 |
| `LegendsViewer-<version>-linux-x64.zip` | Linux x64 |

Unzip and run `LegendsViewer`. The interface opens at `http://localhost:15422`, with the API on
`15421`.

macOS builds are not published here: those targets are signed and notarised with Apple credentials
this fork does not have. Use the
[upstream releases](https://github.com/Kromtec/LegendsViewer-Next/releases) for macOS.

## Installation for Development

### Prerequisites

- **.NET 10 SDK**: [Download here](https://dotnet.microsoft.com/download/dotnet/10.0)
- **Node.js**: [Download here](https://nodejs.org/)

### Backend

Building the solution also builds and hosts the Vue frontend:

```bash
git clone https://github.com/Hadows/LegendsViewer-AIPowered.git
cd LegendsViewer-AIPowered
dotnet restore
dotnet run --project LegendsViewer.Backend
```

The API listens on `http://localhost:15421` and the web app on `http://localhost:15422`.

### Frontend with hot reload

From `LegendsViewer.Frontend/legends-viewer-frontend`, with the backend already running:

```bash
npm install
npm run dev
```

### Tests

```bash
dotnet test LegendsViewer.sln
```

Frontend tests are run separately with `npm run test:run`.

> **Known issue, inherited from upstream:** two concurrency tests in `BookmarkServiceTests` fail on
> Windows. `BookmarkService` writes `bookmarks.json` without serializing concurrent writers, and
> Windows enforces the file share mode where Linux does not — which is why CI, running on Ubuntu,
> stays green. The in-memory state is thread-safe; only the persistence is not.

## Usage

1. Export a world from Dwarf Fortress and load its XML in the app.
   - At minimum `<savename>-<datestamp>-legends.xml`
   - For maps and much more data, also `<savename>-<datestamp>-legends_plus.xml`, produced when
     exporting with DFHack
   - The text exports `-world_history.txt` and `-world_sites_and_pops.txt` are optional but carry
     civilization races, worship lists and rulers, which are otherwise missing
2. Explore the map to discover sites and their locations.
3. Parsed worlds are saved as bookmarks for quick access in future sessions.
4. Switch between worlds from the overview.

To query a world programmatically instead, see [ANALYSIS-API.md](ANALYSIS-API.md).
